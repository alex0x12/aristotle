# Аристотель

Собеседник, который отвечает как Аристотель — опираясь не на общее
представление модели о нём, а на индексированный корпус его подлинных
сочинений на английском.

Главное свойство продукта: **каждая размеченная выдержка проверяется
механически, без доверия модели на слово**. Когда собеседник приводит цитату
(маркер `en:`), клиент сверяет её с текстом именно той главы, чей адрес он
заявил маркером `cite:`, — эти слова, в этом порядке, в узком окне текста
главы, а не где угодно в корпусе. Обычная проза ответа (всё, что не
размечено как `cite:`/`en:`) этой проверке не подвергается вовсе. Если
цитата не находится в заявленной главе среди реально пришедших глав, врезка
так и печатается — с пометкой `[!] нет в выдержках`, прямо на экране, а не
спрятанной в логах. Собеседник видит подлог сразу же, а не после
самостоятельной проверки по книге.

Реализация — на двух языках: Go (сам агент) и Python (сборка корпуса).

- `cmd/aristotle/` — точка входа CLI (флаги, REPL, `-eval`).
- `internal/` — ядро агента: `chat` (цикл хода и вызовов поиска),
  `corpus` (поиск и фронтматтер), `config` (профили провайдеров),
  `provider` (Anthropic и OpenAI-совместимые клиенты), `persona` (загрузка
  промпта личности), `render` (парсер маркеров, ANSI-печать, сверка цитат),
  `eval` (загрузка `eval/questions.yaml` и метрики).
- `persona/` — промпт личности: кто говорит, как, каким методом, какова
  карта позиций, каковы правила ответа (`01-who.md` … `05-contract.md`).
- `eval/questions.yaml` — контрольные вопросы для замеров (раздел «Замеры»
  ниже).
- `corpus/` — 1411 файлов markdown, по одному на главу: 29 подлинных работ
  Аристотеля на английском (20 с Internet Classics Archive при MIT, 9
  с Wikisource). Коммитится целиком.
- `build/` — конвейер сборки корпуса на Python (см. раздел «Как собрать
  корпус заново»).
- `SOURCES.md` — переводчики, годы издания, число глав и обоснование прав.
- `docs/superpowers/` — спецификация и план разработки.

## Как запустить

```bash
go build -o aristotle ./cmd/aristotle
./aristotle
```

Запускать нужно из корня репозитория (бинарник ищет `persona/` и `corpus/`
рядом с собой) либо с флагом `-root /путь/до/aristotle` из любого места.

Нужен ключ облачного провайдера в переменной окружения. Профиль по умолчанию —
`deepseek`, ключ `DEEPSEEK_API_KEY`. Всего профилей четыре:

| Профиль | Модель | Переменная окружения |
|---|---|---|
| `deepseek` (по умолчанию) | `deepseek-v4-pro` | `DEEPSEEK_API_KEY` |
| `openai` | `gpt-5.6` | `OPENAI_API_KEY` |
| `openrouter` | `anthropic/claude-opus-5` | `OPENROUTER_API_KEY` |
| `claude` | `claude-opus-5` | `ANTHROPIC_API_KEY` |

Профиль `claude` собран и проходит модульные тесты (см. `internal/provider/anthropic`),
но живым вызовом не проверялся — на момент последней волны правок ключа
`ANTHROPIC_API_KEY` не было под рукой.

## Как это выглядит

```
> Что такое эвдемония одним предложением? Приведи цитату.

Эвдемония — не состояние, а деятельность души сообразно добродетели, и притом
лучшей — созерцательной — её частью, прожитая в полноте жизни.

│ было сказано, что она есть добродетельная деятельность души известного рода
│ — Nicomachean Ethics I.13

Стало быть, счастье — дело, а не обладание.
```

Это дословный (не сочинённый) обрывок живого прогона: цитата действительно
нашлась в главе `nicomachean-ethics/i/13.md`, поэтому пометки `[!]` нет.
Если бы модель сослалась на главу, в которой такой строки нет, врезка
выглядела бы так: `│ — Nicomachean Ethics I.13 [!] нет в выдержках` — красным,
прямо в потоке ответа.

## Команды и флаги

В беседе:

- `/src` — показать ссылки на главы, использованные в последнем ответе.
- `/model [имя]` — без аргумента печатает текущий профиль и список
  доступных; с аргументом переключает профиль на середине беседы.
- `/again` — повторить последний вопрос независимым ходом (например, если
  первый ответ не задействовал поиск).
- `/quit` — выйти.

Флаги командной строки:

- `-root <путь>` — корень репозитория, если бинарник запущен не из него.
- `-model <профиль>` — профиль провайдера при старте (иначе — умолчание
  из конфига, `deepseek`).
- `-resume <файл>` — продолжить беседу из журнала (`.jsonl`), сохранённого
  предыдущим запуском.
- `-eval <файл>` — прогнать вопросы из файла (например, `eval/questions.yaml`)
  и выйти, не открывая интерактивный режим. Аргумент обязателен.
- `-recall-only` — вместе с `-eval`: посчитать только recall поиска, без
  обращений к модели (быстро, без затрат на API).

## Как собрать корпус заново

Корпус коммитится в `corpus/`, так что для обычного использования пересборка
не нужна — клонировал и работает. Если всё же нужно (новый источник, правка
парсера):

```bash
cd build
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

python build.py            # собрать в corpus/, не трогая уже скачанное
python build.py --force    # пересобрать с нуля
```

Сборка читает `build/works.yaml` (реестр из 29 работ), качает тексты
(с кэшем в `build/.cache/`), разбирает их по главам и перезаписывает
`SOURCES.md` с фактическим числом глав. Переводчики, годы издания и
обоснование прав на воспроизведение — в [`SOURCES.md`](SOURCES.md).

Тесты конвейера: `cd build && python -m pytest tests/ -v`.

Корпус ищется через `qmd` — локальный поисковый индекс с семантическим
поиском, общий для всех проектов на машине:

```bash
qmd collection add /path/to/aristotle/corpus --name aristotle --pattern '**/*.md'
qmd context add qmd://aristotle/ "Полный корпус Аристотеля по-английски, один файл на главу, с полями authenticity и group во frontmatter"
qmd embed -c aristotle
```

После правки корпуса (например, пересборки одной работы) индекс нужно
обновить: `qmd update && qmd embed -c aristotle` — `qmd update` находит
изменившиеся и новые файлы, `qmd embed` считает для них эмбеддинги.

## Замеры

Прогон `./aristotle -eval eval/questions.yaml -recall-only` (только recall,
без обращений к модели) и `./aristotle -eval eval/questions.yaml` (полный,
с проверкой выдумок) — точка отсчёта для будущих правок
`persona/04-doctrine.md`. Признак правки, которая стоит внимания: recall упал
или выдумки не нулевые.

- **Дата:** 2026-09-01, после третьей волны правок.
- **Профиль модели:** `deepseek` (`deepseek-v4-pro`, OpenAI-совместимый API),
  профиль по умолчанию из `internal/config.Builtin`.
- **Recall@6 при наивном запросе, одной попыткой: 5/7 (71%)** — стабильно на
  четырёх независимых прогонах подряд (три `-recall-only` и один полный).
  Это нижняя граница поиска, не оценка системы: `eval/questions.yaml` подаёт
  вопрос в поиск дословно, без переформулировки и без повтора, а живой агент
  так не работает — он переформулирует вопрос в понятиях корпуса по карте
  позиций (`persona/04-doctrine.md`) и может искать до четырёх раз за ход.
  Не находятся `nicomachean-ethics/i/07.md` (счастье) и `metaphysics/iv/03.md`
  (закон противоречия) при дословном запросе из набора — но обе главы
  находятся первой строкой, если спросить в понятиях корпуса, например:
  `what is the good for man final end self-sufficient` → `nicomachean-ethics/i/07.md`
  (100%), `same thing to belong and not belong at the same time same respect
  most certain of all principles` → `metaphysics/iv/03.md` (99%). Это и есть
  работа карты позиций: наивный запрос из семи слов её не использует,
  а сформулированный агентом — использует. Пороговое значение 5/7 из брифа
  задачи 16 не пробито, вопросы не редактировались.
- **Выдуманные выдержки:** 0 из 13 — по всем 10 вопросам (7 recall + 3
  ловушки), каждый на свежей сессии. Число цитат в знаменателе колеблется
  от прогона к прогону (13–14) — модель не всегда цитирует одинаковое число
  раз при одинаковых вопросах, но выдумок не было ни разу.
- **Медиана поиска:** сильно зависит от прогрева локальных моделей `qmd`
  (embedding+generation грузятся в GPU-память заново на каждый холодный
  вызов процесса). На независимых живых прогонах recall-only: первый
  (холодный) вызов — 8.5–8.8 с, последующие (тёплые) — 2.6–2.8 с. `qmd
  search` (чистый BM25, без LLM) укладывается в ~120 мс, но проседает по
  recall до 3/7 — не годится заменой. `qmd vsearch`, несмотря на название,
  тоже дёргает локальную модель расширения запроса: в одном прогоне уложился
  в 2.6 с, но время не гарантировано и в предыдущих измерениях доходило до
  ~10 с — не квалифицируется как надёжный режим «без LLM-расширения».
  Решение: `corpus.Searcher` не менять; полный разбор — в
  `.superpowers/sdd/2026-08-31-aristotle-chat-agent/task-16-report.md`.

## Чего здесь намеренно нет

- **Нумерации Беккера** — источник её не несёт, а ради неё пришлось бы менять
  источник на Perseus с рваным покрытием. Ссылка на книгу и главу проверяема
  и без неё.
- **Русского корпуса второй коллекцией** — цитаты и так честно помечены как
  перевод (`ru:` — «перевод перевода»); вторая коллекция удваивает сборку
  ради косметики.
- **TUI с альтернативным экраном** — потоковый вывод даёт то же самое
  дешевле: врезки видны сразу по мере ответа, без буферизации в отдельный
  экран.
- **Локальной модели** — решено вести через облачный API; локальная модель
  на доступном железе не удержала бы одновременно персону, поиск выдержек
  и качество отыгрыша.
- **Псевдо-аристотелевских сочинений в корпусе.** Часть сочинений,
  традиционно приписываемых Аристотелю («О мире», «Риторика к Александру»,
  «Механика», «Экономика», «О добродетелях и пороках» и другие), ему не
  принадлежит — и дело не только в выборе: их текстов просто нет ни в одном
  из двух источников в пригодном для разбора виде. «Евдемова этика»,
  «О растениях» и «О добродетелях и пороках» на Wikisource лежат
  трансклюзиями Proofread-Page (сырой wikitext несёт только тег `<pages
  index=... />`, без самого текста); «Проблемы» на Wikisource — редирект на
  постороннее произведение (стихотворение Эмили Дикинсон); прочие
  («О мире», «Риторика к Александру» и т. д.) на Wikisource не представлены
  вовсе, а на Internet Classics Archive их никогда не было. Способность
  агента сказать «этого я не писал» на вопрос о таком сочинении поэтому не
  опирается на индексацию его текста — она держится на списке ложно
  приписываемых работ в персоне агента (`persona/`), а не в корпусе.

## Права

Тексты `corpus/` — 28 из 29 работ в общественном достоянии, лицензия
`LICENSE` (MIT) на них не распространяется и покрывает только код
репозитория; двадцать девятая, «On the Soul» (перевод 1931 года), в США
остаётся под охраной авторского права до 1 января 2027 года. Полное
обоснование и таблица переводчиков с годами издания — в
[`SOURCES.md`](SOURCES.md#год-издания-и-одна-работа-1931-года).
